---
title: "Alpha limitations"
description: "Current Stackdome Cloud availability, lifecycle, capacity, and self-hosted compute limits."
---

Stackdome is in alpha. Plan around these current limits:

| Area | Alpha behavior | User continuation |
| --- | --- | --- |
| Cloud availability | Open while capacity is available | Join the availability list or self-host |
| Cloud lifecycle | Ephemeral | Use self-hosted Stackdome for infrastructure you control |
| Account scope | One organization and its default project | No organization or project selection is exposed during alpha |
| Cloud compute | Managed by Stackdome | No cluster setup or selector |
| Self-hosted compute | One connected cluster per organization | Replace the connected cluster if necessary |
| Multi-cluster | Not available during alpha | No user-facing multi-cluster workflow yet |

Cloud and self-hosted installations use the same Stackfile and CLI workflow. If Cloud capacity or ephemerality does not fit the task, follow the [self-hosted installation guide](/self-host/install).

Every signup receives one organization and uses its default project. There is no user-facing organization or project selector during alpha. Cloud users do not choose compute. Self-hosted users connect one cluster for the organization.
