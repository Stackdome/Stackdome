Stackdome is a self-hosted platform-as-a-service you run on your own servers. You point it at a git repository or a container image, and it gives you back a running application on a URL — the same flow you get from a hosted PaaS, except every cluster, database, and domain stays under your control. Underneath it is plain Kubernetes: Stackdome turns what you describe in the dashboard or the REST API into Deployments, Services, and Ingresses on clusters you own. Managed PostgreSQL, encrypted secrets, persistent volumes, custom domains with TLS, and preview environments for pull requests all come from the same install.

## How it works

Stackdome is hub-and-spoke. One **API server** is the hub: it holds all state in PostgreSQL and serves both the REST API and the web UI. Every cluster you register is a spoke running the `stackdome-agent` operator.

When you deploy, the hub writes a Kubernetes custom resource into the target cluster. The agent there reconciles it into real Kubernetes objects — Deployments, Services, Ingresses. Status flows back the other way: the agent writes progress onto the custom resource's status, controllers in the hub watch those changes, PostgreSQL is updated, and the dashboard reflects the new state.

The hub is built to drive many clusters, and every cluster it drives is managed from the same dashboard and the same API. Today, though, each organization registers one cluster — the dashboard says so plainly: "Currently only one cluster is supported." [Add a cluster](/self-host/add-a-cluster) covers what that means in practice.

Once you are signed in, the dashboard is organised around your **Stacks** — your applications — with **Previews**, **Secrets**, **Object Stores**, and **Addons** alongside them, and **Git Providers** and **Image Registries** under integrations for connecting your source code and private images. If you are an organization admin, you also get **Clusters** and **Domains**, where you register the clusters Stackdome deploys to and the domains it issues certificates for.

## What Stackdome is not

- **Not a managed service today.** Everything in this documentation is the self-hosted product: you install the hub on your own server, and it is yours to operate, back up, and upgrade. A managed Stackdome cloud is planned, but it is not what these pages describe.
- **Not a Kubernetes control plane manager.** Stackdome deploys onto clusters, it does not run them. Node capacity, cluster upgrades, and control-plane health stay with you or your cloud provider.
- **Not a router or a certificate authority.** Stackdome does not implement routing or TLS issuance itself. Routing is expressed as ordinary Kubernetes Ingress resources, and certificates are issued by cert-manager — when you install against a real domain, the installer registers a Let's Encrypt issuer for it.
